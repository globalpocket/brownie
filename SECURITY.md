# Security Policy

Brownie is provided for lawful, defensive, research, and productivity purposes.
You are solely responsible for how you use, deploy, modify, or redistribute it.

The maintainers do not authorize use of Brownie for unauthorized access,
credential theft, malware, spam, phishing, evasion, or other harmful activity.
See `ACCEPTABLE_USE.md` for the project acceptable-use policy.

## Reporting vulnerabilities

Please report suspected vulnerabilities privately to the project maintainers
before public disclosure. Include:

- the affected version, commit, or component;
- a concise reproduction path;
- expected and actual impact;
- whether credentials, user data, or remote systems may be affected.

Do not include live secrets, unrelated personal data, or exploit payloads beyond
what is necessary for maintainers to understand and reproduce the issue safely.

## Supported versions

Brownie is pre-release software. Security fixes currently target the active
`main` branch until a versioned release support policy is published.

## Coordinated disclosure

The maintainers aim to acknowledge credible vulnerability reports, assess
impact, and coordinate fixes in good faith. Public proof-of-concept disclosure
should wait until maintainers have had a reasonable opportunity to remediate or
mitigate the issue.
